# 1.3.11 发布说明

本版改桌面端首页的四个板块（改成单行横滚），并解决「播放源加载慢、分类浏览慢」这个长期反馈。其余三端只有版本号变化。

## 首页四个板块改成单行横滚

「发现榜单 / 按分类浏览 / 继续观看 / 我的收藏」原本都用同一个 `.grid` 铺满换行：窗口 1208px 宽时一行只放 6 张，10 条榜单折成两行、第二行孤零零一张，整页被撑到要滚两屏才看得见「我的收藏」。

| 板块 | 改前 | 改后 |
| --- | --- | --- |
| 发现 · 影视榜单 | 多行网格，第二行只 1 张 | 单行横滚，右侧 `›` 翻页 |
| 按分类浏览 | 胶囊换行 | 单行横滚 |
| 继续观看 | 多行网格 | 单行横滚 |
| 我的收藏 | 多行网格 | 单行横滚 |

细节：卡片定宽 168px；左右浮出 `‹` / `›` 圆钮，到边界自动隐藏，点一次滚 `max(260px, 可视宽 × 0.82)`；垂直滚轮在行内转成横向滚动；`ResizeObserver` + `MutationObserver` 重算边界（海报异步加载、数据换批都会改变 `scrollWidth`）；滚动条平时透明、鼠标进到这一行才浮出。分类页与搜索结果仍用网格——那些场景本来就该铺满。

## 分类浏览提速

先量了基线，再对因修：

| 场景 | 改前 | 改后 |
| --- | --- | --- |
| 首页 8 个分类的可用性探测 | 103 940 ms | **15 034 ms** |
| 单分类「电影」首次浏览 | 44 643 ms | **15 015 ms** |
| 首屏第一张卡片出现 | 等整轮完成 | **约 1.1 秒**（边收边渲染） |
| 分类表请求次数 | 13 源 × 8 分类 = **104 次** | **13 次** |

三个根因：

1. **同一个 `?ac=list` 被打了 8 遍**。分类表缓存只在响应回来后才写入，8 个分类并发探测时缓存全部落空。`categoriesOf` 增加在途去重，同一地址的并发请求共用同一个 promise。
2. **`browseCategory` 没有总时限**。最坏耗时是所有源超时之和——魔都、新浪、光速单源就能贡献 20~45 秒。新增 `budgetMs`（默认 15 秒）与内部 `AbortController` 竞速，到点中止在途请求、已收内容照常返回，未答复的源标「超出 15 秒总时限，已跳过」并在分类页提示原因。
3. **首页探测和用户主动浏览抢同一个全局闸门**。探测改用「只看分类表」的快速模式（不再发内容请求），`catalogLimiter` 全局并发从 6 提到 12（单源另有 `sourceLimiter(3)` 兜底）。

两处配套防止越改越差：部分结果按 90 秒短 TTL 缓存（否则只要有一个源每次都超时，缓存永远写不进，用户每次切分类都要重付 15 秒）；探测全失败时退回显示全部 8 个入口且不落盘（不能因为探测失败就把导航藏空）。

快速模式的代价是：源站声明了该分类但内容为空时会高估，点进去看到空态——空态文案本来就是分开的，比等 104 秒划算。

## 验证

- `npm run typecheck`、`npm run lint` 无告警；`npm test` **21 文件 / 364 用例**全过（原 358，新增 6 条覆盖快速探测、分类表在途去重、总时限）。
- 桌面端用 CDP 实测：四个板块 `scrollWidth` 均大于可视宽（发现 1842 / 继续观看 2214 / 我的收藏 2772，可视 1208），分类胶囊单行 7 个；点「体育」进分类页首屏 **1147 ms** 出 40 部，「纪录片」72 部。
- 首页分类入口只剩 7 个不是 bug：13 个源里「少儿」命中 0 个，按设计隐藏。

## 已知限制

- 鸿蒙 HAP 仍用 OpenHarmony 测试根证书自签，HarmonyOS 5/NEXT 真机不认这个链，`hdc install` 会报 `not trusted app source`。要用华为 AGC 签发的调试证书重签：备好 `.cer` / `.p7b` / `.p12` + 别名与密码后跑 `pwsh -File tools/harmony/use-huawei-signing.ps1`。
- 分类浏览的 15 秒是**总预算**，不是每源预算：源特别慢时会有部分源被跳过，结果数比不限时的少（实测 502 → 422 部）。分类页会把「已跳过」的原因和数量显示出来。
- 直播源可播率受网络与源站影响，客户端 15 秒无画面会提示并可换台。
