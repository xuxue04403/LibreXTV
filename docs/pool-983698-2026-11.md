## 1. pool 本身为什么接不进来

站点是 Cloudflare 后面的 SPA，首页 HTML 只有 846 字节，全部逻辑在 `/assets/index-*.js`（约 1MB）。登录 `POST /api/auth/login` 用 JSON `{"username","password"}` 换 `Set-Cookie: vpn_session=<64hex>`，7 天有效。

三条接口线逐条否掉：

**（1）`/api/vod/*`——形态最像，但必须带 cookie。**
站点自己是 MacCMS 聚合器，`/api/vod/list?site=<id>&wd=<kw>&pg=<n>` 的语义和标准 CMS 完全一致（`ac` 参数被忽略，`wd` 真的过滤，`pg` 生效）。理论上 LibreXTV 的 `search.ts` 拼的 URL 能直接打。但匿名一律 401 `{"ok":false,"message":"请先登录"}`，而 `SourceConfig` 没有注入自定义请求头的字段，`cmsRequestHeaders()` 只发 UA 和 Accept。**cookie 塞不进去，这条路断。**

另外 `/api/vod/detail` 只认 `id` 不认 `ids`（只传 `ids` 报 `missing field 'id'`），而 `packages/core/src/detail.ts:36` 拼的是 `?ac=videolist&ids=<id>`。就算解决了 cookie，详情还得改代码。

**（2）`/api/anime/*`——内容是独家的，但协议私有。**
7309 部动漫，`play` 返回的 `raw_url` 是普通 mp4 直链（实测 `v4-kling.kechuangai.com`、`growth-img.xhscdn.com`，250MB 级），**不需要 cookie、不需要 Referer**，能直接播。但拿它得先走 `list → detail → episodes → play` 四步私有链路，还需要「动漫 API Token」——而前端 bundle 里 grep `api_token|api-token|apiToken|Bearer` 零命中，`/api/user/token` 不存在，这个 token 根本没有发放入口。接不进 CMS 模型。

**（3）`/api/movie/*`——线路最全，但有额度且需要后端。**
`/api/movie/play?token=<episode_token>` 一次返回 **31 条线路**，其中约 20 条 `resolve_mode:"direct"` 是标准 m3u8 直链，provider 名字就是资源站名（无水印、牛牛、最大、魔都、新浪、极速、1080zyk、红牛、西瓜、暴风、索尼、豪华、iqiyi、ikun、电影天堂、U酷、猫眼、速播、金鹰、无尽、茅台、360、非凡）。另有 4 条 `resolve_mode:"parse"` 需要解析器。

但要先 `/api/movie/detail` 拿 `episodes[].token`，**按集计费，一天 20 集**（`daily_limit:20`，超出 200 积分/集，`user_points:10`）。LibreXTV 的 CMS 链路没有「二次兑换」这一跳，`detail.ts` 假设 `vod_play_url` 里直接就是可播地址。接不进来。

## 2. 那 40 个上游 maccms 站

`/api/vod/sites` 返回的 `data.video` 里，`kind` 为 `maccms` 的有 40 个、`dongpian` 3 个（短片 / 搜剧 AI / 看剧 AI）。

`dongpian` 那 3 个的详情里 `vod_play_url` 不是地址，而是 **90 字符的 `av_` token**（如 `第1集$av_DHpD6gMLOjIBHHw7Ek`），同样要走 `/api/movie/play` 二次兑换，额度也同上——**不可直接接入**。

剩下 40 个是公开采集站，能绕开 pool 直连。于是做两件事：**找真实域名**、**判是否与内置源同库**。

### 2.1 找真实域名

pool 只给了短 id（`lziapi`、`hhzyapi`、`xgzyapi`…），没给域名。用 `{前缀}{id}{后缀}/api.php/provide/vod` 爆破：

- 第一轮 5 前缀（空 / `www.` / `cj.` / `caiji.` / `api.`）× 4 后缀（`.com` / `.net` / `.cc` / `.tv`）→ 命中 14/40。
- 第二轮针对剩下的 20 个品牌，7 前缀 × 11 后缀（`.com` `.net` `.cc` `.tv` `.vip` `.top` `.xyz` `.me` `.cn` `.la` `.io`）× 2 路径，共 3080 组合 → 新增 4 个命中，其中 `jyzyapi`（金鹰）、`guangsuapi`（光速）**已是内置源**，真正新增的是猫眼 `https://api.maoyanapi.top/api.php/provide/vod` 与虎牙 `https://www.huyaapi.com/api.php/provide/vod`。

判据是「返回合法 JSON 且 `list` 非空」，不是 HTTP 200——很多域名返回 200 但内容是错误页。

### 2.2 判是否同库：不要用域名，要用心片路径

第一版判据是「比对播放 CDN 主机名」，`mirror.ts` 用它判出「速播 ≡ 新浪」（首集都是 `play.xluuss.com/play/9aAjlRPb/index.m3u8`），和 `source-audit-2026-11.md` §4 的历史结论对得上。

**但这个判据是错的。** 后来发现虎牙的 CDN 在三次查询里变了两次（`1080p.huyall.com` → `hd.kuktxu.com`，后者其实是京东的 CDN），而内容一模一样。CDN 域名是按请求分配的，**域名根本不代表库存**。

改用「首集中间分片」做指纹：把 m3u8 逐层展开到分片列表，取中间那个分片，看 `pathname + search`（**丢掉协议和主机**）。路径相同 = 同一份文件 = 同一片库。用四部各家都收的剧（甄嬛传 / 狂飙 / 三体 / 庆余年）交叉验证。

结果非常清楚：

| 《甄嬛传》首集中段分片 | 源 |
| --- | --- |
| `/hls/749/20250929/128057/plist307.ts` | 红牛、金鹰、新浪、光速、**海海**、**虎牙**、**速播** |
| `/20221120/8540_26c091d1/2000k/hls/...` | 非凡 |
| `/20230801/3eUEVTJ5/hls/...` | 360 |
| `/hls/832/20251202/1428540/plist320.ts` | 极速 |

《狂飙》《三体》《庆余年》给出同样的分组，只是分片序号不同。同一份文件挂在不同的 CDN 上：

| 源 | 甄嬛传首集 m3u8 | 分片主机 |
| --- | --- | --- |
| 红牛 | `hn.bfvvs.com/play/PdyPx9zb/index.m3u8` | `hnts.ymuuy.com:65` |
| 金鹰 | `hd.kuktxu.com/play/6dBBjP2d/index.m3u8` | `c.baisiweiting.com:18443` |
| 新浪 | `play.xluuss.com/play/9aADgM7e/index.m3u8` | `g.xlzyd.com:9999` |
| 海海 | `play.hhuus.com/play/9b6x5DOe/index.m3u8` | `p.hhwenjian.com:65` |

**四者的分片路径都是 `/hls/749/20250929/128057/plist*.ts`。**

这个发现的意义：所谓「资源站」很多只是同一个片库的不同 CDN 入口。加一个「新源」不等于加一批新剧。

另一组：**魔都 ≡ 木偶**（四部剧分片路径全同）。这与「按域名判魔都≡魔都动漫」的历史结论不同，是片库级的重复。

## 4. 改动

`defaults/sources.json` v7 → v8，末尾追加两条（**只能末尾追加**：插在中间会让老用户已保存的 `builtin_N` 指向另一个站）：

```json
{ "name": "海海资源", "url": "https://hhzyapi.com/api.php/provide/vod" },
{ "name": "西瓜资源", "url": "https://caiji.xgzyapi.com/api.php/provide/vod" }
```

三份清单文件必须字节一致，改一处拷两处：

- `defaults/sources.json`
- `apps/androidtv/app/src/main/assets/default-sources.json`
- `apps/harmonyos/entry/src/main/resources/rawfile/default-sources.json`

`version` 驱动客户端同步（`apps/desktop/src/renderer/src/lib/defaults.ts:19` 的 `DEFAULTS_VERSION`），必须同步加一。

- 西瓜资源的可播率在 33%~75% 之间波动，比海海（100%）明显低，后续如长期低于 50% 应考虑换掉。
